# 语义层判据

有些 AI 指纹要读懂句意才判得出：同一个概念有没有换名字、两段之间是怎么接上的、冒号前那半句在干什么、三句话是不是一副骨架。正则只能抓固定字面，这四项交给模型逐条判。

判据的思路来自 [lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone) 的语义层实验（约 43 万次结构化判断），数字照录，标签和措辞是本项目重写的。

## 怎么用

1. 长文先抽候选：`stop-slop candidates 稿子.md --out c.json`。没装工具就自己按下面的单位切：每段、每个段间接口、每个正文冒号句、每组连续三句
2. 每条候选只看候选本身，按对应判据从标签表里选一个，附置信度（高 / 中 / 低）和一句理由，写回 `label` / `confidence` / `reason`
3. 按文末口径汇总，过门槛的列进改稿计划

判的时候守四条：

- 只按判据判，不凭"像不像 AI"的整体感觉。整体印象会被文风带偏
- 每条独立判，不回头看全文
- 拿不准就选"无法判断"，不硬判
- 只能用表里的标签，不自造

---

## 1. 同义重命名（每段一条候选）

数一段里"同一个东西换了实义说法"的次数。代词（它、这个）、省略不算，那是正常回指。

| 标签 | 判据 |
|---|---|
| 0 | 每个概念从头到尾一个叫法，或者只出现一次 |
| 1 | 有一个概念换了一次说法，读者要做一次"X 就是 Y"的对应 |
| 2 | 两个概念各换了一次，或一个概念换了两次 |
| 3+ | 换说法三次及以上 |
| 无法判断 | 段落太碎或不是正文 |

例："优化 / 增强 / 提升 / 提高"在一段里轮流指同一件事；同一个工厂项目先后叫"基地""版图""节点""本地产能"。

参考：AI 每段 0.83–0.86 次，人类 0.49；两次以上的段落 AI 占 20.6–22.5%，人类 8.4%。这项只有单模型一轮判读，证据比另外三项弱。

改法：统一回第一次出现的名字。不同的东西恰好用了近义词、术语第一次出现时的"又称 X"不算。

---

## 2. 衔接方式（每个段间接口一条候选）

候选给出上一段末句 a 和下一段首句 b，判 a 到 b 怎么接的。b 开头有连接词时，先看这个连接词标的逻辑关系成不成立。

| 标签 | 判据 |
|---|---|
| 连接词不成立 | b 用了"但是 / 因此 / 于是"之类，读完发现标的关系并不存在或很勉强。优先判这一条 |
| 明确承接 | 围绕同一对象或同一论述继续展开，接得自然；可以换词、用代词、省略 |
| 跳得突然 | 话题相关，但中间缺了一步，读者要自己补 |
| 换了话题 | b 换到基本无关的新话题，没有交代 |
| 无法判断 | 信息不够 |

汇总看最长的连续"明确承接"有几个接口。参考：AI 短文中位 7，人类中位 2；93% 的 AI 文章有 6 连环以上。

改法：连环达到 6 时挑一两个接口，删承接句直接进新话题；"连接词不成立"的接口优先改。

## 3. 冒号分类（每个正文冒号句一条候选）

从上往下判，命中就停。

| 标签 | 判据 |
|---|---|
| 引语 | 人名 / 称呼加发言，或"说 / 表示 / 写道"引出的话 |
| 版式 | 标题、时间戳、比分比例、来源署名这类元数据 |
| 定义 | 冒号前是术语或功能名，冒号后解释它 |
| 引列表 | 冒号前只说"下面有几点 / 几种场景"，不含判断，冒号后是列举 |
| 结论提示 | 冒号前是一句独立的结论性判断（常带"是 / 在于 / 取决于"），冒号后展开论证 |
| 其他 | 以上都不是 |
| 无法判断 | 信息不够 |

只有"结论提示"是信号，AI 约为人类的 2.1–2.2 倍。"引列表"反过来是人类用得多，不改。

例："这组数字说明了一个残酷的现实：……"

改法：删掉提示半句直接写内容；前半句承接上文时只把冒号换成句号或逗号。见 SKILL.md 规则 11。

---

## 4. 高度同构三连（每组连续三句一条候选）

工具用逗号数、长度档粗筛出结构相近的三句，粗筛很宽，判的时候收紧。

| 标签 | 判据 |
|---|---|
| 高度同构 | 三句的主谓宾和补充成分位置一一对应，框架几乎一样，只换了填进去的词 |
| 部分同构 | 主干框架相似，但有成分对不上或多出缺少 |
| 只有词重复 | 重复了某些词，句法组织不同 |
| 只有意思并列 | 讲的是同类的几件事，句法不同 |
| 无关 | 没有对应关系 |
| 无法判断 | 句子残缺 |

参考：宽口径（结构相近就算）人机都高，AI 71.1%、人类 56.2%，区分不开；高度同构这一档 AI 29.4%、人类 10.7%。AI 不是更爱排比，是排得更死。

例："叫什么名字？承载什么功能？嵌入哪个生态？"

改法：打散其中一句，合并、拆分或换语序，内容一项不删。演讲稿里刻意的排比、清单、叙事里先后发生的三件事不改。见 SKILL.md 规则 13。

## 汇总口径

| 指标 | 算法 | 人类 | AI | 列入改稿计划的门槛 |
|---|---|---|---|---|
| 同义重命名 | 各段次数之和 ÷ 段数 | 0.49 | 0.83–0.86 | ≥0.7 次/段，或 2 次以上的段落占比 >15% |
| 衔接连环 | 最长连续"明确承接"接口数 | 中位 2 | 中位 7 | ≥6 |
| 结论冒号 | "结论提示"条数 | 低 | 约 2.1 倍 | 有一条就看，多条优先 |
| 高度同构三连 | "高度同构"组数 | 10.7% | 29.4% | ≥2 组 |

门槛以下的单条命中，确实读着别扭也可以改，但不要在报告里说成"统计上像 AI"。
